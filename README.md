# 热搜连刷（hot-search-web）

机主自用「连刷」当日各版报纸的纯静态页（网页 v4 版次制，2026-10-07 拍板 C）。
GitHub Pages 托管（main 分支根目录），**只放链接与文本，全仓库零密钥**。

## v4 版次制（当前形态）

一推=一版报纸：目录按版分区（**第 N 推 · HH:MM**），各版编号各自 #1 起；
不是"接着上午往下补"——每版都是全新一张报纸。数据=Worker `/api/state`
按 editions 一次全量返回（lean 免费字段：编号/标题/作者/时长/发布/粉丝/
窗口赞·峰值/热度·峰值/窗口播放·峰值/赞播比·峰值；无真赞/评/转/藏）。

- **目录**：每版一个分区，标题「第 N 推 · HH:MM」；头部常驻当日版数/最新版时刻/
  已刷到位置（第 E 推 #n/N）/换暗号/原帖域名切换/倒计时三档；`document.title`
  实时同步「第 E 推 #n/N · 热搜连刷」。
- **补后接力**：打开/刷新重读 `/api/state`，群里「补」挂末版尾部的条目自然列出
  （编号续该版）；无专门补模式。
- **接力指针按 vid 锚定**：新版插入/日清切换不漂移；跨系统日标记自动作废。
- **原帖地址**（aweme_id 拼接，真机 A/B 选默认）：默认 `iesdouyin.com/share/video/{id}/`，
  头部可切换 `douyin.com/video/{id}`（存 localStorage）。
- **单看模式**（连刷关闭）：点标题/条目跳该条原帖，返回后不自动跳。
- **连刷模式**（后悔药与 v4.2 一字不动）：「▶ 开始连刷 / 继续 第E推 #n」同标签跳当前条
  原帖 → 看完按浏览器返回 → 倒计时横条「即将播放 第E推 #n+1」（三档 1s/1.5s/2s
  进度条 + 「↺ 重看」「⏸ 暂停连刷」）→ 到点无操作自动接下一条（同版尾部→下一版首条；
  最后一版末尾→结束页「当日已推 N 版 · 全部刷完 · 想继续到群里发『补』」）。
  「■ 停止连刷」常驻；F5/重开从 localStorage 恢复 relay 状态与进度（vid）。
- **系统日=北京时间 06:01 切**（batchplan/Worker/本页三处同规则）：<06:01 归前一天，
  网页仍显示昨天最后一版（防刷一半被清）；06:01 后自动切新系统日（空目录等首推）。
  `?date=` 考古后门透传给 Worker。
- **不做**：沉浸式播放器、iframe、抓视频流地址、播完自动跳转、下载视频本体、
  补按钮、任何写操作。

## v4 去真赞化（历史）

JIT 真赞揭示整体退役：网页不再调用 `/api/batch`，全站不出现「揭示/解锁/花费」概念。
条目不显示真赞/评/转/藏，只带池内免费四指标（峰值口径），非零才显示。

## 数据通道

```
本页（纯静态零密钥） → Cloudflare Worker 公开代理（hot-search-daily 仓 worker/）
```

只有一个端点：`GET /api/state`（当日各版全量；读 data 分支批次状态文件，
零 TikHub 调用、零花费）。暗号鉴权（401 自动重弹框）。

## 暗号（拍板 e'）

暗号**禁止硬编码**进本仓库任何文件（公开仓库源码人人可读）。首次打开弹输入框，
用户手动粘贴暗号，存 `localStorage` 永久记住；之后每次请求带 `X-Hotsearch-Token` 头。
清浏览器数据/换浏览器/换设备才需重输。暗号值在 Cloudflare Worker 的
`WEB_PROXY_TOKEN`（Secret）里配置。

## 本地自验（零网络）

起任意静态服务后开 `index.html?mock=1`（file:// 双击亦可，自动 mock）：
全走 `mock/fixture.js` 假数据（第 1 推 08:30 12 条 + 第 2 推 15:20 10 条，
各版 #1 起）+ `mock/post.html` 模拟原帖页。可完整走一遍：粘暗号 → 两版分区 →
开始连刷（最新版 #1）→ 返回 → 倒计时 → 自动接下一条 → 点第 1 推 #5 编号=从该条续刷
→ F5 显示「继续 第1推 #6」→ 补后场景（?mocktopup=1）末版 #11~#20 自然列出 →
末尾出结束页「当日已推 2 版 · 全部刷完」。
mock 专属测试钩子：`?setvid=eNvNN` 预设指针；`?relay=on/off`；`?slow=1` 倒计时放慢；
`?hold=1` 横条冻结；`?mocktopup=1` 补后场景。
